LLM 应用安全 / 结构化查询

StruQ：使用结构化查询防御提示注入

论文提出把开发者指令和用户数据拆成两个明确通道，并训练模型只遵循 prompt 通道指令，从根源上缓解数据中注入指令的问题。

核心创新

双通道输入

用结构化格式显式隔离可信 prompt 与不可信 data，避免模型把用户数据误当成任务指令。

结构化指令微调

从非 instruction-tuned 基座模型出发，构造干净样本与带攻击样本，使模型学会忽略 data 通道中的指令。

安全前端

前端负责注入特殊格式和保留 token，使攻击者无法伪造合法分隔符，从而削弱 completion 类攻击。

技术路线

  1. 威胁建模

    攻击者可控制 data，但不能修改系统 prompt 或安全前端格式；攻击成功定义为模型服从隐藏恶意指令。

  2. 攻击覆盖

    评估 Naive、Ignore、Escape、Completion、HackAPrompt、TAP、GCG 等手工与优化攻击。

  3. 数据增强

    训练集中 50% 保持干净，另外 50% 注入 Naive 或 Completion-Other 攻击，使模型输出仍对齐原任务。

  4. 安全-效用评估

    用攻击成功率衡量安全，用 AlpacaEval win rate 衡量正常任务效用。

关键指标

维度结果
手工攻击StruQ 将所有测试手工攻击的成功率降至 <2%。
TAP 攻击在 Llama 上将 Tree-of-Attacks with Pruning ASR 从 97% 降至 9%。
GCG 攻击在 Llama 上将 GCG ASR 从 97% 降至 58%，说明白盒优化攻击仍具挑战。
效用影响AlpacaEval win rate 基本保持，Mistral 上降幅约 0.7%，论文认为接近统计边界。

研究亮点

  • 不是简单提示工程，而是输入协议、前端约束和模型训练的组合防御。
  • 对未在训练中出现的优化攻击有一定泛化，但诚实呈现 GCG 仍能突破的边界。
  • 把 prompt/data 分离抽象成通用接口，为 LLM 应用安全工程提供清晰设计范式。
